## 3. F-01 與高音壓補充測試

### 3.1 三分之一倍頻程輸入

新增網格直接從官方 C 的 RAP／DLL 表取門檻，涵蓋 11 低頻帶、適用範圍內各門檻的前一 ULP／相等／後一 ULP／±1e-6 dB、120 dB，及固定種子 200 組隨機輸入。每個聲場 605 案；不將 >120 dB 當成正常接受輸入。

| 聲場 | 案例／比響度值 | 最大總響度差（sone） | 最大比響度差（sone/Bark） | 嚴格容差失敗 |
|---|---:|---:|---:|---:|
| free | 605／145,200 | 0.068200117071 | 0.053062560721 | 0 |
| diffuse | 605／145,200 | 0.019771444290 | 0.216246913118 | 0 |

容差為 `max(0.1, 0.05 × |reference|)`；不是相加。最大絕對差超過 0.1 不自動代表失敗，還要核對該點的 5% 範圍。這些是獨立工程回歸，非官方新增 Annex B 訊號。

25 Hz band = 118.000001 dB、其他 band = −60 dB，總響度由舊版 **154.93** 改為 **52.51 sone**；官方 C 為約 **52.514908816**。直接核心層的重大錯誤確實消除。

### 3.2 2 秒、25 Hz、119 dB SPL 壓力正弦

用同一份 f64 壓力陣列，C／Rust 各自重新計算；未使用專案測試內的常數當預期結果。

| free field 指標 | Rust 修正後 | 官方 C | 判定 |
|---|---:|---:|---|
| 定常 N，C TimeSkip=0.2 s | 56.24 | 56.704172426 | 總響度 PASS |
| TV Nmax | 56.877222211 | 56.878693537 | 最大值 PASS；不代表整條曲線通過 |
| TV N(t) 同時刻最大差 | 0.216836272 | — | 1／1,000 點超過嚴格幅度；發生於 2 ms |
| TV 比響度同時刻最大差 | 0.716762266 | — | 56／240,000 值超標，位於 0、2、4 ms |
| stream N(t)，由零開始、不丟暖機 | 最大差 0.002800784 | — | 全 1,000 點嚴格幅度 PASS |

對 TV 再套用 ±1 個 2 ms 時間點的包絡：總響度 PASS，**240 條 Bark 曲線中 18 條仍 FAIL**，共有 27 值超出放寬包絡；scalar／AVX2、free／diffuse 結論一致。這是對額外高音壓訊號使用相同包絡規則的工程診斷，不是將它冒稱為官方 Annex B 案例。結果與仍存在的 batch 初始化問題一致；只比較 Nmax 的回歸測試會漏掉它。

stream 在 free／diffuse、scalar／AVX2 下，固定 480 samples、交錯 1／23／24／95／96／97／511／1024 samples、以及預先執行後 reset 再以 127 samples 分塊，N 與 flags 均 bitwise 相同；clamped、nonfinite flags 均為 0。free scalar 與 batch 在第 580 幀後最大差為 `1.6189929397e-9` sone。這是核心 streaming API 的證據，**不等於已驗證 panel f32 校準／GUI／實際載入版本**。

### 3.3 定常比響度差異的定位

固定 C TimeSkip=0.2 s 時，free field 的 240 個比響度值中 **66 個超過嚴格容差**，位置為 11.6–18.1 Bark；總響度卻仍通過。不可把「總響度 PASS」延伸成「比響度 PASS」。

進一步把完全相同的 28 band level 分別送入兩個核心：

- 使用 Rust 前端產生的 levels：兩核心 N 差 `0.001423219639` sone、比響度最大差 `0.000780163272`，0 個超標。
- 使用 C 前端的 levels：各指定 TimeSkip 下，兩核心比響度最大差約 `0.00078018`，0 個超標。
- 只將 C TimeSkip 改成 0 s 的診斷，Rust 與 C 原生前端的比響度最大差變為 `0.099756793728`、0 超標；改成 0.5 s 仍為 66 超標。

因此目前證據指向 **定常前端濾波與時間窗契約差異**，沒有顯示 F-01 選列修正錯誤。Rust `noct_spectrum_rms` 使用 MoSQITo 的降採樣／NOCT filters 並平均全段；C 採其參考 filter bank，可指定 TimeSkip。本報告仍保留預先採用的 **0.2 s 主比較結果**；不因 0 s 較容易通過就換掉驗收設定。是否應新增設定或改前端，仍需對正式條文、API 語意與既有相容性作決策；暫不定性為另一個已證實 ISO 條文違反。

## 4. Annex B、校準、對齊與工具可信度

- 官方來源 C 未修改，以 MSVC `/O2 /fp:precise` 重新建 DLL 與 CLI；所有 44 個解壓附件仍與原 ZIP 相同。
- 24 WAV 均為 mono／PCM16／48 kHz。C 與 NumPy `/32768` 解碼相同；Annex C calibration gain **2.835797716391444**，兩算法差 **0**，校準後 RMS **0.02 Pa**、回算 **60.0 dB SPL**。
- C ABI size／offset 為 `24 / 0 / 8 / 16`；輸出使用 NaN 預填、前後 sentinel，檢查完整寫入與沒有越界，WAV 壓力輸入也核對前後 hash。
- 官方 CLI 與 DLL 的 N、比響度最大差均 < `5.00001e-5`，符合 CSV 四位小數捨入；沒有靠重新校準或平移曲線貼合答案。
- 20 組 TV 的共同 N 時間點共 48,711；B.4 的全部 Bark 共 5,568,000 比響度值／後端。兩後端與 C 共同點皆通過嚴格幅度判定。
- XLSX 的 20 條總響度＋8 條指定 Bark 曲線，C／Rust scalar／Rust AVX2 共 **84 個判定均為 0 嚴格例外、0 放寬例外**；5 組 stationary 也通過其 N 與比響度界限。
- Rust／CLI／XLSX 共同時間點最大差 **0 秒**；8 組總響度長度不同：14、15、16、17、18、23、24、25。明列差異，不把 `min(length)` 後成功當完整 shape PASS。C specific 的額外尾點亦另驗。
- XLSX 公式重新計算 **720,122 個**，另核對 **1,446 個數值常數**；0 公式錯誤。這不代表 N5 使用哪一欄、哪個時間窗的語意正確。
- 外部 fail-closed 判定器 **19 個負向控制通過**：空值、NaN／Inf、shape、邊界、容差相加陷阱、99／100／101 點與 1% 比例、包絡反轉與端點不環繞等。
- 精確 1% 的形式界線尚有資料來源疑點；本輪正式 84 個判定全部 0 例外，因此此歧義不改變這一批 PASS。

官方資料疑點仍保留：signal 12／13 的 N5 指向 E 欄；18／22／24 的 N5 範圍與備註窗不一致；CLI percentile 與 Excel 定義不同；USL[12][4] 的 0.24／0.22 尚待授權標準全文裁定。本輪沒有擅改官方表格或 golden。
